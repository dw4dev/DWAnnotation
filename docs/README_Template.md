# {ProjectName} 文件庫 (Documentation)

本目錄存放 {ProjectName} 專案的所有規格與架構文件。為了讓開發過程（尤其是與 AI 協作時）保持清晰且高效，文件遵循特定的結構與讀取策略。

## 目錄結構說明

```text
docs/
├── current.md              # 當前工作指引（必讀）
├── AI_Rules.md             # AI 協作與開發的核心規則（必讀）
├── specs/                  # 主版本規格書與模板
│   ├── 00VersionSpecTemplate.md
│   └── spec-vX.Y.md        # 當前/歷史版本的規格書
├── phases/                 # 各版本的階段任務拆解
│   └── vX.Y/
│       ├── Phase-01.md
│       ├── Phase-02.md
│       └── ...
├── kb/                     # 知識庫 (Knowledge Base)
│   └── coding_rules.md     # 共用開發規範、架構守則等
└── adr/                    # 架構決策紀錄 (Architecture Decision Records)
    └── .gitkeep            # （待正式技術決策時建立）
```

## 核心文件說明

### 1. `current.md`
**當前工作上下文**。包含了專案目前的整體進度、下一步開發目標、技術細節與已知問題。每次啟動新任務時，應優先讀取此檔案以掌握現況。

### 2. `AI_Rules.md`
**AI 協作規則**。規範了與 AI Agent 協作開發時的流程與禁止事項。

### 3. `specs/` 目錄
**版本規格書**。以完整的業務目標與系統架構為主，定義了該版本的所有範圍、功能與非功能需求。

### 4. `phases/` 目錄
**階段任務文件**。將大型版本規格書拆解成可獨立開發、驗收的「階段 (Phase)」。負責定義單一階段的具體實作目標與驗收條件。

### 5. `kb/` 目錄
**知識庫文件**。存放所有開發相關的共同規範與領域知識。

### 6. `adr/` 目錄
**架構決策紀錄**。當遇到需要權衡多種方案的技術決策時，會在此建立一份文件記錄當時的背景、考量與最終決定。

## 文件讀取策略 (Retrieval Strategy)

為了避免一次性載入過多無關資訊，影響理解或超出上下文限制，請依循以下順序讀取文件：

1. **優先讀取** `current.md`（了解當前進度與重點）。
2. **接著讀取** `phases/vX.Y/Phase-XX.md`（了解本次任務的具體規格）。
3. **視需要查閱** `kb/` 內的知識庫文件（確認實作規範與領域知識）。
4. **視需要查閱** `specs/spec-vX.Y.md` 或 `adr/`（當需要了解全局架構或技術決策背景時）。
